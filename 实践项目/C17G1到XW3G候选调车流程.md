# C17G1 到 XW3G 候选调车流程

## 1. 文档定位

本文档用于固化当前阶段的候选调车流程，方便后续咨询专业人员并补充进路表、拓扑表和联锁条件。

当前候选进路：

```text
C17G1 -> 咽喉区 -> XW3G
```

当前结论：

- 该进路可作为远程调车 DMI 原型的候选展示路径。
- 当前尚未确认完整真实联锁数据。
- 在真实数据确认前，红框内咽喉区可暂时抽象为 `THROAT_1`、`THROAT_2` 两个临时区段。
- 后续应使用真实轨道电路编号、道岔编号、定位/反位要求和敌对进路信息替换临时抽象。

## 2. 调车换线的基本物理逻辑

列车本身不会像汽车一样主动横向变道，也不是列车的轨道自动发生整体移动。

真实换线依靠道岔完成：

1. 联锁系统提前办理从起点到目标线的调车进路。
2. 进路上的相关道岔转换到指定位置。
3. 道岔确认到位并锁闭。
4. 始端调车信号开放。
5. 列车低速前进。
6. 车轮经过道岔尖轨时，被钢轨几何导向到目标线路。
7. 列车沿咽喉区连接线进入目标股道或目标轨道区段。

一句话概括：

```text
列车不主动跨线，是道岔提前排好进路，钢轨把列车导向另一条线。
```

## 3. 候选调车业务流程

### 阶段 1：故障停车

业务状态：

- 故障列车停在 `C17G1`。
- 车载 ATO/自动驾驶退出或不可用。
- ATP 保持制动。
- 地面远程控制尚未接管。

DMI 展示：

- 当前区段：`C17G1`
- 目标区段：`XW3G`
- 进路状态：`未建立`
- 道岔状态：`未锁闭`
- 信号状态：`关闭`
- 制动状态：`制动`
- 速度：`0 km/h`
- `C17G1` 显示占用。

### 阶段 2：远程接管

业务状态：

- 地面远程操作员申请接管故障列车。
- 控制权从车载自动控制或本地控制切换为地面远程控制。
- 列车仍保持停车，制动不立即缓解。

DMI 展示：

- 控制状态：`远程接管`
- 模式：`调车/远程调车`
- 通信状态：`正常`
- 事件提示：`地面端取得远程接管权限`

### 阶段 3：请求调车进路

业务状态：

- 操作员请求办理候选调车进路：

```text
R_C17G1_XW3G
```

- 起点暂定为 `C17G1`。
- 终点暂定为 `XW3G`。
- 始端信号机、终端信号机或终端停车点待确认。

DMI 展示：

- 进路状态：`请求中`
- 起点区段：`C17G1`
- 目标区段：`XW3G`
- 候选进路路径以虚线或待确认颜色显示。

### 阶段 4：联锁条件检查

业务状态：

系统检查调车进路能否建立，至少包括：

- 起点列车占用状态正确。
- 目标区段 `XW3G` 空闲。
- 咽喉区相关轨道区段空闲。
- 相关道岔可转换。
- 相关道岔无挤岔、无失表、无锁闭冲突。
- 没有敌对进路。
- 防护信号机处于可控状态。
- 远程控制通信链路正常。

DMI 展示：

- 进路状态：`联锁检查`
- 检查项可逐项显示为 `通过/未通过`。
- 如果存在未确认项，显示为 `待确认`，不应伪装成真实联锁结果。

### 阶段 5：道岔转换与锁闭

业务状态：

- 咽喉区内相关道岔按进路要求转换。
- 每组道岔到达规定位置。
- 道岔进入锁闭状态。
- 此时列车仍未启动。

道岔位置含义：

```text
定位：列车沿道岔默认方向运行
反位：列车被导向侧线或另一条连接线
```

DMI 展示：

- 道岔状态：`转换中 -> 锁闭`
- 进路状态：`已锁闭`
- 已锁闭进路显示黄色。
- 非进路线路显示灰色。

### 阶段 6：调车信号开放

业务状态：

- 始端调车信号开放。
- 列车获得低速调车移动许可。
- 牵引控制允许，但受调车限速约束。

DMI 展示：

- 信号状态：`允许调车`
- 始端信号机显示绿色或允许状态。
- 调车限速显示，例如 `40 km/h`。
- 事件提示：`调车信号开放，允许低速运行`

### 阶段 7：低速启动

业务状态：

- 地面远程端下发低速启动或牵引级位。
- 列车从 `C17G1` 起动。
- 速度逐步上升，但不得超过调车限速。

DMI 展示：

- 牵引级位：`1级` 或低速牵引。
- 速度从 `0 km/h` 增加。
- `C17G1` 仍显示占用，直到列车尾部出清。
- 目标距离开始递减。

### 阶段 8：进入咽喉区第 1 区段

业务状态：

- 列车离开起点股道，进入咽喉区入口。
- 道岔已经锁闭，列车轮对沿钢轨被导向目标方向。
- 当前临时抽象为：

```text
THROAT_1
```

DMI 展示：

- 当前占用区段：`THROAT_1`
- `C17G1` 可显示为出清或尾部占用，具体取决于仿真粒度。
- 进路仍保持锁闭。
- 列车图标进入红框所示咽喉区。

### 阶段 9：通过咽喉区第 2 区段

业务状态：

- 列车继续通过道岔群核心区域。
- 根据道岔位置组合，列车被导向 `XW3G` 方向。
- 当前临时抽象为：

```text
THROAT_2
```

DMI 展示：

- 当前占用区段：`THROAT_2`
- 道岔状态：`锁闭`
- 进路状态：`占用通过`
- 已通过区段可显示出清，未通过锁闭区段继续显示黄色。

### 阶段 10：进入目标区段 XW3G

业务状态：

- 列车进入目标区段 `XW3G`。
- 咽喉区逐步出清。
- 系统准备目标停车控制。

DMI 展示：

- 当前区段：`XW3G`
- 目标区段：`XW3G`
- `XW3G` 显示占用。
- 目标距离继续递减。
- 进路仍保持锁闭，等待列车停稳和作业完成。

### 阶段 11：制动停车

业务状态：

- 根据目标距离和制动距离判断，触发常用制动。
- 列车速度逐步下降至 0。
- 列车停稳在 `XW3G` 目标停车位置附近。

DMI 展示：

- 制动状态：`制动`
- 牵引级位：`0`
- 速度：递减至 `0 km/h`
- 目标距离：递减至 `0 m`
- 事件提示：`目标股道停车`

### 阶段 12：停车确认与进路解锁

业务状态：

- 远程操作员确认列车停稳。
- 调车作业完成。
- 信号关闭。
- 进路解锁。
- 道岔恢复可操作状态。

DMI 展示：

- 当前区段：`XW3G`
- 进路状态：`完成/已解锁`
- 信号状态：`关闭`
- 道岔状态：`解锁`
- 控制状态：`远程接管保持` 或 `退出接管`
- 事件提示：`C17G1 至 XW3G 调车完成`

## 6. 需要咨询确认的信息

当前项目定位是仿真展示原型，不是正式联锁系统设计。因此咨询问题应收束到“能否支撑一个逻辑自洽、可演示、可验收的最小闭环”。

不需要一开始追求完整真实工程深度。真实轨道电路编号、道岔编号、敌对进路等内容可作为后续增强项。

## 7. 第一版完成指标

在上述核心问题基本确认后，第一版仿真应达到以下完成指标：

1. DMI 能显示候选进路 `R_C17G1_XW3G`。
2. `C17G1`、`THROAT_1`、`THROAT_2`、`XW3G` 至少四个区段可视化。
3. 进路建立后，候选路径高亮。
4. 道岔组状态能从 `未锁闭` 变为 `转换中`，再变为 `锁闭`。
5. 始端调车信号能从 `关闭` 变为 `允许调车`。
6. 列车图标能沿候选路径连续移动，不发生跳线。
7. 区段占用能按顺序转移：`C17G1 -> THROAT_1 -> THROAT_2 -> XW3G`。
8. 速度、目标距离、公里标与列车移动联动。
9. 接近目标点后进入制动停车，最终停在 `XW3G`。
10. 文本信息区能记录完整流程：接管、请求进路、联锁检查、道岔锁闭、信号开放、低速调车、进入目标区段、停车完成、进路解锁。

## 8. 后续实现原则

- 在未确认真实进路表前，DMI 中应标注为“候选进路”或“演示进路”。
- 不能把 `THROAT_1/THROAT_2` 表述为真实区段编号。
- 动画应表现为列车沿锁闭进路通过道岔被导向 `XW3G`，不要表现成列车横向跳转。
- 图纸只作为离线拓扑来源，运行时不直接读取 DWG。
- 下一步代码实现应采用结构化拓扑数据，而不是在绘图函数中零散硬编码。
