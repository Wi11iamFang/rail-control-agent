## 2. 列车调车转线作业流程（专业口径讲解）

### 2.1 术语定位：先分清三件事

| 术语 | 含义 | 对应本项目 |
|---|---|---|
| 调车作业 | 列车/车列在站内、段所内不载客（或空车）的移动、编组、转线等作业，速度低、距离短 | 整个仿真场景 |
| 调车进路 | 联锁为一次调车作业办理的、从始端调车信号机到终端（停车点/信号机）的固定路径，含道岔位置、区段、敌对条件 | `R_C17G1_XW3G` |
| 转线作业（转线） | 调车作业的一种：车列从一条线（股道/存车线）经咽喉区道岔进入另一条线 | `C17G1 -> 咽喉区 -> XW3G` |

**推荐专业表述**（替换 `THROAT_1/THROAT_2` 阶段名）：

- 主表述：**调车进路建立后的调车运行阶段**
- 强调换线：**经由咽喉区的调车转线作业**
- 联锁/信号系统角度：**调车进路占用通过阶段**

### 2.2 完整流程（按真实作业顺序）

**前置阶段（运行前完成）**

1. **调车进路办理（进路请求与联锁检查）**
   - 操作员请求办理 `C17G1 -> XW3G` 调车进路。
   - 联锁检查：起点列车占用状态、目标区段空闲、咽喉区轨道区段空闲、道岔可转换、无敌对进路、防护信号状态、通信链路正常。
   - 资料依据：调研报告第 17 页（人员防护开关纳入联锁进路检查，禁止办理经由封锁区域的调车进路）。

2. **道岔转换与进路锁闭**
   - 进路上相关道岔转换到进路要求位置（定位/反位），确认到位后锁闭。
   - 进路建立后**进路锁闭保持**——锁闭的是"进路"，道岔与区段随之被锁闭，列车尚未运行。
   - 资料依据：本项目现有文档阶段 5；CTCS2 教材第 33 页（"列车通过时进路锁闭、解锁的安全性"）。

3. **调车信号开放**
   - 始端调车信号机开放（允许调车显示），车列获得移动许可。
   - 车载转入**调车模式（SH）**，按调车运行规则监控（顶棚限速监控，司机/远程操作员负责安全运行）。
   - 资料依据：司机操作手册第 36~37、77 页；CTCS2 教材第 25 页。

**运行阶段（本次要讲清楚的"低速调车开始到进入目标区段"）**

4. **车列进入进路内方**
   - 调车信号开放后，车列低速启动，压入始端信号机内方。
   - 含义：车列从此处于该调车进路的防护范围内，进路由"锁闭等待"转入"占用通过"。

5. **进路锁闭保持（调车进路占用通过阶段）**
   - 运行过程中进路持续保持锁闭，道岔不得再转换，敌对进路不得办理。
   - 说明：调车速度低，一般不设接发车进路那样的"接近锁闭"；重点是**进路锁闭保持**与后续**分段解锁**。若汇报中需要体现联锁深度，可写"接近锁闭或进路锁闭保持"作为待确认项。

6. **轨道电路占用顺序转移**
   - 车列头部进入咽喉区第一个轨道电路区段，该区段显示占用；起点股道区段在车列尾部出清后恢复空闲。
   - 占用按运行方向逐区段前移：`C17G1（占用）-> 咽喉区段1（占用）-> 咽喉区段2（占用）-> XW3G（占用）`。
   - 这是"区段占用顺序转移"的标准含义，DMI 动画应表现占用光带逐段移动，而不是列车图标跳线。

7. **车列通过咽喉区（道岔导向转线）**
   - 车列轮对经过锁闭道岔的尖轨/辙叉，被钢轨几何导向目标线路方向——**列车不主动跨线，是道岔排好进路后钢轨导向**。
   - 咽喉区经道岔弯股的进路通常不电码化（无码区），因此本阶段的安全由"进路锁闭 + 地面调车信号 + 低速限速"共同保证，不依赖机车信号连续信息。
   - 资料依据：CTCS2 教材第 32~33 页（咽喉区侧线无码区）。

8. **进入目标轨道区段**
   - 车列进入 `XW3G`，目标区段占用；咽喉区各段随车列出清依次解锁或保持至停车。
   - 此时进入目标停车控制：根据停车点（防护点）与安全距离计算制动曲线。

9. **制动停车与进路解锁**
   - 按目标距离-速度曲线常用制动停车；停稳并确认作业完成后，信号关闭、进路解锁（分段解锁或一次性解锁）、道岔恢复可操作。
   - 资料依据：安全距离讲座第 1~2 页（停车点设在防护点前适当距离，其间为安全距离）。

## 3. 项目实现规划

### 3.1 状态机命名改造（核心动作）

把状态枚举从"按临时区段命名"改为"按业务阶段命名"，`THROAT_1/THROAT_2` 只保留在**拓扑数据**中作占位区段，不再出现在状态机与 DMI 流程文案中：

```text
FAULT_STOPPED                故障停车（C17G1 占用）
REMOTE_TAKEOVER              远程接管（控制权交接，RRM/CAM 场景）
SHUNT_ROUTE_REQUESTED        调车进路请求（R_C17G1_XW3G）
INTERLOCK_CHECKING           联锁检查（敌对进路/道岔/区段/通信）
SWITCH_MOVING                道岔转换
ROUTE_LOCKED                 进路锁闭（锁闭保持）
SHUNT_SIGNAL_OPEN            调车信号开放
TRAIN_ENTERED_ROUTE          车列进入进路内方
ROUTE_OCCUPANCY_TRANSFER     占用顺序转移（起点出清 -> 咽喉区段占用）
THROAT_PASSING               车列通过咽喉区（道岔导向转线）
ENTERED_TARGET_TRACK         进入目标轨道区段（XW3G 占用）
TARGET_BRAKING               目标制动停车
STOP_CONFIRMED               停稳确认
ROUTE_RELEASED               进路解锁（信号关闭、道岔解锁）
```

DMI 事件流文案对应（汇报口径）：

```text
故障停车 -> 远程接管 -> 办理调车进路 -> 联锁检查通过 -> 道岔转换并锁闭
-> 调车信号开放，车载转入调车模式 -> 车列进入进路内方
-> 轨道电路占用顺序转移，车列经咽喉区锁闭道岔转线
-> 进入目标区段 XW3G -> 制动停车 -> 停稳确认，进路解锁，调车完成
```

### 3.2 数据/对象模型（为替换真实进路表预留）

用结构化数据取代硬编码，四类对象一次建好：

```text
区段对象 TrackSection：{ id, name, length, type: 股道/道岔区段/咽喉连接线, isReal }
道岔对象 Switch：      { id, normalPosition, reversePosition, state: 定位/反位/转换中/锁闭/挤岔 }
信号对象 Signal：      { id, type: 调车信号机, state: 开放/关闭, 对应进路 }
进路对象 Route：       { id: R_C17G1_XW3G, sections[], switches[], 始端信号, 终端停车点,
                         敌对接发车/调车进路[], 解锁方式: 分段/一次 }
```

第一版占位：

| 占位对象 | 类型 | 后续替换 |
|---|---|---|
| `C17G1` | 股道/存车线（真实代号） | 保留 |
| `THROAT_1` | 咽喉入口区段（临时占位） | 真实轨道电路编号 |

> 本阶段属于调车进路建立后的调车运行过程。列车在调车信号允许后低速启动，压入进路内方，经由咽喉区锁闭道岔完成转线，轨道电路占用由起点区段逐步转移至目标区段。当前仿真将咽喉区暂抽象为两个待确认区段（`THROAT_1/THROAT_2`），仅作为拓扑占位，后续由真实进路表和轨道电路编号替换。

### 3.6 需确认事项更新（在原有 7 问基础上补充）

1. 调车模式（SH）下的限速按 CTCS2 技术条件/运营规定取值，候选 40 km/h 与目视/引导模式顶棚一致，是否可接受？
2. 咽喉区两个占位区段的真实轨道电路编号、道岔编号及定位/反位要求。
3. 始端调车信号机对象（`XC17`/`SCF17`/`XCF17` 或实际调车信号机）。
4. 停车点位置：`XW3G` 内、信号机前还是车挡/绝缘节前（涉及安全距离）。
5. 进路解锁方式：分段解锁还是一次性解锁。
6. 是否在 DMI 中体现"调车危险"信息与"禁止调车"（ETCS-132）防护演示（可作高价值安全防护展示点）。

---

## 4. 一句话总结

`THROAT_1/THROAT_2` 只是仿真里的**临时区段占位**，不应出现在流程阶段命名中；业务上该过程叫**调车进路建立后的调车运行阶段**（强调换线时称**经由咽喉区的调车转线作业**，站在联锁角度称**调车进路占用通过阶段**），其本质是：信号开放 -> 车列进入进路内方 -> 进路锁闭保持 -> 轨道电路占用顺序转移 -> 车列经锁闭道岔通过咽喉区 -> 进入目标轨道区段 -> 停车后进路解锁。
